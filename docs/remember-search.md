# 리멤버 통합검색

2026-11-03 공개 [공고 목록](https://career.rememberapp.co.kr/job/postings)과 해당 페이지의 검색 요청·공개 분류 정보를 확인했다. 화면 자동화는 실행하지 않았다.

- 조회: `POST https://career-api.rememberapp.co.kr/job_postings/search`. `page`, `per: 30`, `sort: starts_at_desc`, `search`를 JSON으로 보낸다. 검색어는 `keywords`, 직무는 `job_category_ids`, 지역은 `addresses`, 경력 범위는 `min_experience`·`max_experience`다. camelCase 필터는 무시되는 것을 확인해 wire 형식인 snake_case를 사용한다.
- 분류: 공식 `https://open-profile-api.rememberapp.co.kr/v2/open_profiles/options?version=2`의 직군·직무 이름과 ID만 `remember-categories.json`에 정적으로 보관한다. 지역은 네이티브 시도 이름을 사용한다. 런타임 분류 조회 권한은 추가하지 않는다. 직무 분류가 사이트마다 달라 공통 직군은 가까운 범주로 연결한다.
- 경력: 네이티브 `career_year: -1`은 경력무관 공고만 반환하며 동시에 전달한 연차 범위를 덮어쓴다. 경력무관과 신입·경력을 함께 고르면 별도 검색을 합친다. 신입과 최소 2년 이상처럼 선택 범위 사이에 간격이 있으면 신입·경력·무관을 최대 세 요청으로 나눈다. 모든 분기에는 같은 검색어·직무·지역·페이지를 전달한다. 한 분기라도 실패하면 해당 묶음 전체를 실패로 두어 같은 페이지를 재시도한다.
- 연차는 리멤버의 지원 가능 범위 겹침 의미를 따른다. 예를 들어 신입~3년 조건에도 3~7년 공고가 포함될 수 있다. 공고의 최대 요구 경력을 브라우저에서 다시 잘라내지 않는다.
- 페이지: `meta.page`가 요청과 일치하는지 확인하고 `meta.total_pages`로 다음 페이지를 판단한다. 분기 결과를 공고 ID로 합치며 다음 페이지는 하나 이상의 분기에 남아 있을 때 가져온다. 원문 링크는 `/job/posting/{숫자}`로 생성하고 외부 지원 링크·추적 URL은 사용하지 않는다.
- 인증: 쿠키·인증 헤더·API 키·기기 ID·조회 세션 ID를 보내지 않는다. 원래 검색의 지원 공고 제외는 사용하지 않고, 지원 기업 제외는 기존 로컬 지원 이력 색인으로 처리한다. 검색 응답에서 기업명·공고명·ID·지역·경력·마감일만 추린다. 채용 담당자·프로필·지원 상태·설명·이미지는 저장하지 않는다.
- 권한: `https://career-api.rememberapp.co.kr/*`를 검색용으로 추가한다. 기존 검색 사이트 선택과 검색어·필터는 유지하며 신규 기본값에는 네 사이트를 포함한다. 리멤버 결과에도 기존 지원 이력 모달·지원 기업 제외·북마크를 적용한다.

실제 HTTP 확인: React + 프론트엔드(311) + 서울 + 신입~3년은 3건을 반환했다. 프론트엔드 첫 두 페이지는 각각 30건이었고 중복이 없었다. 경력무관을 함께 선택한 조회와 존재하지 않는 검색어의 빈 결과도 실제 클라이언트·파서를 통과했다. 단위 테스트는 조건 변환, 응답 정제, 경력 OR, 오류·취소·타임아웃, 다음 페이지·재시도, 지원 이력·북마크 연결을 검사한다. 실제 확장 화면 확인은 사용자 확인 범위로 남긴다.
