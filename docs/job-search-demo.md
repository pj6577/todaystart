# 브라우저 직접 요청 통합검색 데모

0.11.0의 실험 기능으로 관리 화면 → **공고 통합검색**에서 실행한다. 직군·개발 세부 직무·근무 지역·경력을 선택하거나 검색어를 입력한다. 별도 수집 서버, API 키, 신규 확장 권한은 사용하지 않는다. 검색 결과는 해당 화면의 메모리에만 보관하며 지원 기록·메모·일정 DB나 백업에 추가하지 않는다.

## 실행

```sh
npm run build
```

Chrome 확장 프로그램 관리에서 기존 로컬 설치를 새로고침하고 관리 화면을 다시 연다. 주소 끝에 `#search`를 붙이거나 왼쪽 **공고 통합검색**을 선택한다. GitHub 0.11.0 릴리즈에 포함하며 Chrome 웹스토어 게시 작업은 별도다.

임시 Chromium 프로필로 실제 검색을 시험하려면 다음 명령을 사용한다. 실제 계정에 로그인하지 않으며 기존 브라우저 데이터와 분리된다.

```sh
npx playwright install chromium
npm run demo:search
```

## 요청 경로

| 사이트 | 직접 요청하는 경로 | 파싱 |
| --- | --- | --- |
| 사람인 | `/zf_user/search?searchword=…&recruitPage=…&recruitPageCount=20` | 검색 결과 HTML의 `#recruit_info_list .item_recruit` |
| 잡코리아 | `/Search/?stext=…&tabType=recruit&Page_No=…` | 검색 결과 HTML의 `CardJob` 카드 |
| 원티드 | `/api/chaos/search/v1/position?query=…&country=kr&limit=12&offset=…` | 검색 페이지가 사용하는 별도 JSON 목록 |

원티드는 HTML 자체에 공고가 없어 공개 검색 클라이언트에서 확인한 목록 요청을 사용한다. 제휴 OpenAPI와는 다르며 안정적인 외부 제공을 보장하는 인터페이스가 아니다. 검색 페이지나 원격 스크립트를 실행하지 않는다. 요청 경로는 코드에 고정하며 응답이 제공한 다음 페이지 URL을 그대로 호출하지 않는다.

## 동작과 한계

- 직군 20개, 개발 세부 직무 12개, 국내 지역 16개, 경력 3종과 최소 경력 신입~20년·최대 경력 1~20년을 제공한다. 검색어 없이 조건만으로 검색할 수 있다.
- 직군·직무, 지역, 경력, 검색 사이트은 하나의 통합 모달을 해당 메뉴에서 연다. 직군→세부 직무 탐색, 지역 이름 검색, 경력 선택, 검색 사이트 체크를 같은 모달에서 전환한다. 메뉴를 오가도 임시 선택은 유지하고 ‘적용’ 때 모든 조건과 사이트를 한 번에 확정해 처음부터 검색한다. 취소·Escape·바깥 클릭은 임시 선택을 버린다. 직군·세부 직무·지역·경력은 복수 선택을 지원한다. 왼쪽 직군 목록은 탐색용이며 오른쪽 체크박스가 실제 검색 조건이다. 선택 항목은 중립색 배경·테두리와 체크 표시로 구분한다.
- 직군 전체를 체크하면 해당 세부 직무 선택을 비우고, 세부 직무를 체크하면 그 직군 전체를 해제한다. 다른 직군 선택은 유지한다. 지역의 ‘전국’과 경력의 ‘전체’는 해당 항목의 선택을 비운다. 선택 칩은 각각 해제할 수 있다. 여러 값은 사이트의 쉼표 구분 파라미터에 묶어 보내며 조합별로 요청을 늘리지 않는다.
- 경력에는 전체·신입·신입~3년·2~5년·5년 이상 빠른 조건, 신입/경력/경력무관 포함 체크, 최소·최대 연차 선택을 제공한다. 연차 선택은 경력을 자동으로 포함하고, 경력을 해제하면 연차도 지운다. 최대 연차는 최소 연차보다 커야 하며 잘못된 범위는 적용할 수 없다. 한쪽 연차는 비워 상한 또는 하한만 지정할 수 있다. 조건 칩에 범위를 표시하고 다음 페이지에도 그대로 유지한다.
- 최소 경력의 ‘신입’은 내부 값 0으로 처리한다. 사람인에는 `exp_cd=1`과 하한 없는 경력 범위로, 잡코리아에는 `careerType=1,2`와 `careerMin=0`으로 전달한다. 양의 최소 연차를 고르면 신입을 해제하며, 신입 포함을 다시 켜서 별도로 추가할 수도 있다. 신입을 해제하면 0 하한도 함께 지워 표시와 요청이 어긋나지 않게 한다.
- 적용한 조건은 개별 해제 가능한 칩으로 표시한다. 칩 해제도 결과를 갱신하며, 검색어 없이 마지막 조건까지 지우면 검색을 중지하고 초기 화면으로 돌아간다. 데스크톱은 조건 도구를 스크롤 중에도 유지하고 모바일은 같은 통합 모달이 하단에 열린다. 필터 버튼은 기본 배경과 hover 배경을 구분한다.
- ‘검색 사이트’ 안에서 검색할 사이트를 선택하고 적용한다. 검색창 아래 ‘지원 기업 제외하기’는 현재 결과에 즉시 적용하며 지원 이력 배지와 같은 완료 기록 색인을 사용한다. 제외 때문에 화면에 결과가 늘지 않으면 자동 요청을 반복하지 않고 다음 공고 버튼으로 이어 읽을 수 있다. 결과 상단에는 현재 가져온 건수를 총건수처럼 표시하지 않는다.
- 0.11.1부터 마지막으로 검색하거나 적용한 검색어·조건·사이트와 지원 기업 제외 설정 한 건을 로컬에 저장해 화면 재진입·새로고침·새 탭에서 복원한다. 모달에서 취소한 값과 아직 검색하지 않은 입력은 저장하지 않는다. 설정을 복원할 때 자동 요청하지 않으며 검색 결과·응답 원문·검색 이력 목록은 저장하지 않는다. 전체 초기화와 개별 칩 해제도 마지막 설정에 반영한다.
- 사람인은 `cat_mcls` 또는 `cat_kewd`, `loc_mcd`, `exp_cd` 또는 `exp_none`, `exp_min`·`exp_max`에, 잡코리아는 `duty`, `local`, `careerType`, `careerMin`·`careerMax`에 조건을 반영한다. 코드 매핑과 연차 검증은 `src/search/filters.ts`에 있다.
- 잡코리아의 5자리 직군 코드는 검색 필터로 바로 보내지 않는다. 공개 검색 코드 목록(`/Search/api/codes/jobClassification`)에서 확인한 7자리 세부 직무 코드들로 펼쳐 `duty`에 전달한다. 코드 목록은 개인정보 없이 `src/search/jobkorea-groups.json`에 보관한다. 직군 전체와 프론트엔드 단일 직무에 서울·신입 조건을 적용한 공개 HTTP 응답에서 각각 공고 카드 25개를 확인했다.
- 직군은 두 사이트의 분류가 달라 가까운 범주를 연결한다. 마케팅·MD와 식음료·서비스 등은 복수 범주로 묶는다. 모든 사이트가 동일한 직무 범위를 보장하는 것은 아니다.
- 오늘시작의 원티드 직군·지역·경력 조건 연결은 아직 구현하지 않았다. 조건을 선택하면 ‘조건 검색 연결 전’으로 표시하고 요청하지 않는다. 이 상태는 오늘시작의 구현 범위이며 원티드 사이트의 조건 검색 가능 여부를 나타내지 않는다. 조건을 무시한 키워드 결과를 섞지 않는다.

- 검색 버튼 또는 조건 적용을 누를 때 선택한 사이트마다 GET 요청 1회를 보낸다. 검색 중에는 먼저 도착한 결과부터 표시한다.
- 쿠키·인증정보는 보내지 않는다(`credentials: omit`). 검색어와 접속 IP 등 일반 네트워크 정보는 조회 대상 사이트에 전달된다. 오늘시작 운영 서버로는 전송하지 않는다.
- 검색·지원 기록·캘린더·메모·설정은 대시보드와 같은 공통 최대 너비 1440px와 반응형 여백을 쓴다. 결과는 데스크톱 3열·태블릿 2열·모바일 1열로 표시한다. 결과 하단에 접근하면 다음 페이지를 요청해 기존 카드 뒤에 추가하는 무한 스크롤이다. 버튼으로도 다음 결과를 가져올 수 있다.
- 요청은 사이트당 한 번에 한 페이지씩 처리한다. 요청 페이지의 검증 상한은 사이트당 1,000페이지다. 다음 페이지가 없거나 이전과 같은 목록을 반환하면 멈춘다. 화면의 공고 수는 실제 가져온 수다. 오류가 난 사이트는 자동 재시도하지 않는다.
- 추가 조회·재시도는 해당 검색에서 확정한 조건을 유지한다. 패널 안의 임시 선택은 적용하기 전까지 기존 결과의 조회 조건을 바꾸지 않는다. 결과 하단에 접근하면 이어 읽으며, 주기 수집이나 탭 열기는 하지 않는다. 중지는 자동 추가 조회도 멈춘다.
- 같은 사이트의 공고 ID만 중복 제거한다. 다른 사이트의 같은 기업 공고는 별개로 유지한다. 도착한 페이지 순서로 추가하고 기존 카드의 위치를 바꾸지 않는다.
- 지원 완료 기록을 기업명으로 색인해 법인 표기·공백을 정규화한 이름이 같은 공고에 지원 이력 배지를 표시한다. `아인잡(AINJOB)`·`AINJOB(아인잡)`처럼 괄호로 한영 이름을 병기한 경우 검색 전용 비교 키에서 한글 이름으로 연결하므로 `㈜아인잡`의 이력을 찾을 수 있다. 같은 언어의 괄호 설명과 지점·계열사 구분, 영문 지역·조직 표기는 보존한다. 괄호 없는 영문명만으로 한글 기업명을 추측하거나 철자 유사도만으로 연결하지 않는다. 배지와 ‘지원 기업 제외하기’는 같은 키를 쓴다. 저장한 기업명·기록 식별자·병합 규칙은 변경하지 않는다. ‘지원 이력 있음’ 배지를 누르면 모달에 이전 직무·경로·날짜·기업명과 각 공고 링크를 보여준다. 내역은 최근 지원일 순으로 나열하고, 지원일 미확인 기록은 마지막에 둔다. 내역이 많으면 모달 목록만 스크롤하며 닫기·Escape·바깥 클릭 후 원래 배지로 포커스를 돌려준다. 지원 취소·확인 대기·상태 불명은 제외한다. 이 비교는 브라우저에서만 수행하며 로컬 지원 기록을 검색 사이트로 보내지 않는다.
- 목록에 없는 지역·마감일 등은 상세 페이지 추가 요청으로 보강하지 않는다.
- 20초 타임아웃, 6MiB 응답 크기 제한을 둔다. 중지·새 검색·검색 화면 종료 시 진행 중 요청을 취소한다.
- 접근 제한·로그인 필요·인식 실패·타임아웃은 ‘결과 없음’과 구분한다. 추가 페이지 실패 시 먼저 가져온 공고는 유지한다.
- 외부 HTML은 실행하거나 화면에 삽입하지 않는다. 텍스트와 허용된 공고 HTTPS 링크만 새 카드로 렌더링한다. 원문 링크의 추적 쿼리는 제거한다.

이후 사용자가 제공한 통합 필터 모달 이미지를 기준으로, 왼쪽 메뉴와 직군·세부 직무 2단 탐색을 한 모달에 구성했다. 적용/취소, 선택 칩, 모바일 배치는 오늘시작의 조건 요청과 브라우저 직접 검색에 맞춰 구현했다. 참고 사이트의 동작을 그대로 복제하거나 모든 사이트가 같은 방식을 쓴다고 주장하지 않는다.

## 확인한 범위 — 2026-11-02

Node의 공개 HTTP 요청에서는 사람인 검색 HTML 20개, 잡코리아 검색 카드 22개, 원티드 검색 JSON 12개를 확인했다. **이 결과가 Chrome 확장 프로그램의 직접 요청 성공을 의미하지는 않는다.**

임시 프로필의 headless Chromium 확장 페이지에서는 같은 검색어 `frontend`로 **잡코리아 22개**를 읽었다. 사람인은 20초와 별도 45초 확인에서 응답 시간이 초과됐고, 원티드는 HTTP 403을 반환했다. 두 사이트의 브라우저 직접 요청은 아직 성공하지 못했다. 접근 제한을 우회하거나 탭 방식으로 자동 전환하지 않는다. 실제 사용자의 Chrome 환경에서도 세 사이트가 모두 작동한다고 보장할 수 없다.

조건 검색을 추가한 뒤 같은 임시 Chromium 확장 환경에서 검색어 없이 **프론트엔드·서울·신입**을 선택해 잡코리아 첫 페이지 25개와 두 번째 페이지까지 총 50개 공고를 읽었다. 실제 요청의 `duty=1000230`, `local=I000`, `careerType=1`이 두 페이지에 유지됐다. 이는 사이트가 해당 조건으로 반환한 목록을 읽은 결과이며, 유료·추천 공고 등 사이트 제공 결과의 조건 일치 여부를 별도 보장하지 않는다.

복수 선택을 추가한 뒤 공개 HTTP 요청으로 프론트엔드·백엔드, 서울·경기, 신입·경력을 함께 전달했다. 사람인 HTTP 200·공고 카드 20개, 잡코리아 HTTP 200·공고 카드 25개를 확인했다. 이 검사는 쿠키 없는 직접 HTTP 요청이며 확장 프로그램 UI나 사이트의 모든 결과가 조건을 엄격히 만족함을 보장하는 검사는 아니다.

2026-11-02 연차 범위를 연결하면서 사람인의 공개 `components/option/Career.js`와 잡코리아 검색 화면의 `FilterCareer` 코드를 확인했다. 프론트엔드 ‘신입 포함·최대 3년’과 ‘2~5년’을 각각 공개 HTTP로 요청해 사람인 20개·잡코리아 25개 공고 응답을 확인했다. 사람인 서버의 검색 초기값에도 `exp_cd`·`exp_min`·`exp_max`가 전달한 범위대로 반영됐다.

합성 응답을 사용한 브라우저 검사는 세 사이트 결과 합치기, 사이트 필터, 무한 스크롤과 기존 카드 순서, 부분 실패·수동 재시도, 쿠키 미전송, 저장소 분리, 새 검색·중지 시 이전 응답 무시를 다룬다. 복수 선택·전체/세부 직무 전환·개별 해제·원티드 조건 미지원·3열 가운데 정렬·추가 조회 조건 유지·모바일 폭·키보드 선택창·지원 기업 비교도 검사한다. 선택 배경의 명도 차이와 체크 표시를 라이트·다크에서 확인한다. 합성 검사와 실제 사이트 연결 결과를 구분한다.

```sh
npx vitest run tests/unit/job-search.test.ts
npm run build
npx playwright test tests/e2e/job-search.spec.ts
node scripts/search-demo.cjs --smoke
```

실제 연결 검사의 사이트별 상태·요청 URL·카드 수와 다크/라이트 화면은 `.tmp/search-demo/`에만 저장한다. 스모크 명령의 종료 코드만으로 세 사이트 성공을 판단하지 않고 `live-result.json`의 `complete`와 각 사이트 상태를 확인한다. 빌드 중에는 브라우저 검사를 실행하지 않는다.
