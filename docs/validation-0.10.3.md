# 0.10.3 — 지원창 열람과 실제 제출 구분

관련 이슈: [#4](https://github.com/pj6577/todaystart/issues/4). 수정 커밋: `aaf7886`.

## 재현과 수정 범위

기존 빌드에서는 잡코리아 지원창을 열고 닫기만 해도 `started` 시도가 `unverified`로 바뀌어 ‘확인 필요’ 카드가 표시됐다. 합성 지원창으로 이 순서를 재현했으며, 제출 POST와 저장된 지원 기록은 모두 0건인데 관리 화면에 안내가 남는 것을 확인했다.

- 열람만 한 탭을 닫으면 종료 시각만 보관하고 `started`를 실패로 바꾸지 않는다.
- 잡코리아의 미확정 진행 안내는 관찰한 제출 요청의 `requestId`가 있는 경우에만 표시한다. 버튼 클릭 후 확인창 취소나 HTML 필수 입력 검사로 중단되면 안내하지 않는다.
- 이전 버전이 만든 제출 근거 없는 `unverified`도 안내와 묶음 건수에서 제외한다. 원본 지원 시도와 지원 기록은 삭제하지 않는다.
- 실제 제출 요청의 결과를 놓친 안내, 명시적 완료 표시, 지원 현황에서 가져온 독립적인 완료 근거는 계속 처리한다. 원티드의 별도 클릭·완료 경로 관찰은 유지한다.

## 검사

- TypeScript 검사와 단위 테스트: 43개 파일, 501개 테스트 통과.
- 프로덕션 빌드와 관련 브라우저 시나리오 28개 통과.
- 팝업·iframe 각각 지원창 열기, 최종 확인창 취소, 입력 미완료의 6개 경우에서 POST·지원 기록·진행 안내가 생성되지 않는지 확인한다. 탭 종료와 관리 화면 재시작 뒤에도 동일하다.
- 실제 form 제출 후 결과 미확인 안내, 완료 표시와 결과 문서의 연결, 반복 창, 제출 전·숨김·다른 공고 표시 배제, 가져오기 대조, 기존 안내 묶음·수동 확인을 함께 검사한다.
- 기존 네 건 대조 fixture에서는 잡코리아의 클릭만 관찰한 세 건을 미확정 안내로 띄우지 않지만, 독립적인 지원 현황을 가져오면 네 건 모두 대조되고 기록이 중복되지 않는지 검증한다.

실제 로그인 계정이나 실제 입사지원 요청은 사용하지 않는다. 제보 당시 네 건의 접수 여부와 조회 범위·수집 누락은 확인되지 않았으므로 #4 전체를 해결로 닫지 않는다. 사람인 완료 레이어의 기존 수정도 포함하지만 #5의 실사용 최종 확인 상태는 바꾸지 않는다.

## 설치 파일

- `release/todaystart-0.10.3.zip`: 확장 빌드만 포함한 설치 ZIP. Git에는 바이너리를 추가하지 않고 GitHub 릴리즈 자산으로 게시한다.
- `release/todaystart-0.10.3.sha256`: 파일 무결성 확인용 SHA-256.
- `release/todaystart-0.10.3-validation.json`: ZIP 무결성·빌드 파일 일치·매니페스트 참조·권한·라이선스·민감 패턴 검사 결과.

이전 ZIP은 덮어쓰지 않는다. 기존 설치 폴더의 파일을 교체한 뒤 확장 프로그램, 관리 화면과 열려 있는 채용 사이트 탭을 새로고침한다. Chrome 웹스토어 게시 작업은 포함하지 않는다.
