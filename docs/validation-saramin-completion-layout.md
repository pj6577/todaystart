# 사람인 지원 완료창 레이아웃 검증

관련 이슈: [#5](https://github.com/pj6577/todaystart/issues/5)

## 원인과 재현 근거

2026-10-28에 비로그인으로 열 수 있는 사람인 공고의 `setQuickApplyLayerPosition()`과 [공통 CSS](https://www.saramin.co.kr/sri_css/common_ui_keeping.css)를 확인했습니다. 기존 완료 레이어 `#iframe_layer`는 `position:absolute`이며 열 때의 스크롤 위치를 `top`, 뷰포트 높이를 픽셀 단위 `height`로 저장합니다. 닫기 버튼은 그 레이어의 가운데에서 위로 360px 떨어져 있습니다.

해당 배치 규칙을 기업·공고·이력서 정보가 없는 로컬 fixture로 재구성했습니다. 실제 지원 요청은 보내지 않았습니다. 기존 확장 빌드로 완료 iframe에 진입해 기록을 저장하면 공고 헤더 아래에 높이 156px의 오늘시작 이력 안내가 추가됩니다. 브라우저가 본문 스크롤을 보정하면서 절대 배치된 레이어가 위로 밀렸습니다.

1919×943 뷰포트의 측정 결과:

| 항목 | 안내 삽입 전 | 기존 빌드의 삽입 후 | 수정 빌드, 완료창 표시 중 |
| --- | ---: | ---: | ---: |
| 본문 scrollY | 900px | 1056px | 900px |
| 딤 상단 | 0px | -156px | 0px |
| 딤 하단 | 943px | 787px | 943px |
| 닫기 버튼 상단 | 약 111.5px | 약 -44.5px | 약 111.5px |

기존 빌드의 회귀 테스트는 레이어 상단 기대값 `0` 대신 `-156`으로 실패했습니다. 딤 끝 `787px`, 위로 사라진 닫기 버튼, 거의 화면 위에 붙은 완료 패널은 제보 이미지와 같은 형태입니다. 사용자의 실제 로그인 세션과 원본 완료 문서에서 측정한 값은 아니므로 모든 사이트 변형을 재현했다고 보지는 않습니다.

## 변경과 검사

- 지원창이 열려 있는 동안 안내 DOM의 삽입·교체·제거를 보류합니다. 원래 안내가 있으면 유지하고, 닫으면 최신 기록·테마·표시 설정을 반영합니다.
- 사이트의 완료 레이어·iframe·스크롤·닫기 핸들러는 수정하지 않습니다. 닫힌 상태로 새로 삽입된 레이어나 숨겨진 새 지원창 iframe은 안내를 막지 않습니다.
- 완료 문서 관찰과 로컬 저장은 계속 동작하며, 완료창을 닫은 뒤 이력 안내가 표시되고 완료 기록 한 건이 유지되는지 브라우저에서 확인했습니다.
- 동적 레이어 교체·제거, 조상 표시 상태, 두 레이어의 전환, 관찰자 해제와 보류 후 표시 상태 갱신을 단위 검사합니다.

검증: TypeScript 검사, 단위 테스트 458개, 확장 빌드와 사람인 관련 브라우저 회귀 검사 9개 통과. 새 ZIP·스토어 배포는 포함하지 않습니다. 실제 사이트에서의 최종 확인 전까지 이슈를 열어 둡니다.
