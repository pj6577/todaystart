# 성능 개선과 소스 공개 정책

## 성능 개선

2026-10-27, 버전 0.9.2 작업 트리 기준. 개인정보를 사용하지 않는 합성 데이터로 로컬 Node에서 측정했다. 기업 이름은 서로 다르며 공고마다 일치하는 이력이 한 건인 조건이다. 아래 시간은 브라우저 전체 로딩 시간이 아니라 해당 함수의 반복 실행 중앙값이다.

| 작업 | 개선 전 | 개선 후 |
| --- | ---: | ---: |
| 기록·연결 각각 5,000건, 마지막 연결 조회 20회 | 2,625.84ms | 1.20ms |
| 공고 40개·지원 이력 1,000건, 정확/정규화 기업 비교 | 47.47ms | 0.07ms |
| 공고 40개·지원 이력 5,000건, 정확/정규화 기업 비교 | 236.43ms | 0.05ms |

개선 후 기업 색인 생성 비용은 별도이며, 1,000건은 약 0.40ms, 5,000건은 약 1.75ms다. 색인은 지원 기록과 취소 표시 설정이 바뀔 때 갱신한다. 유사 이름 검색의 최초 검색 시간은 위 표에 포함하지 않았다. 유사 검색용 Fuse 색인은 기능을 사용할 때 생성하며, 동일 기업의 결과는 탭 안에서 최대 256개까지 재사용한다.

- 지원 연결 조회의 이중 탐색을 제거했다. 메모 보드와 지원 선택기는 연결별 기록 지도를 재사용한다.
- 기업명과 사이트별 기업 ID에 색인을 만들었다. 서로 다른 사이트의 ID를 비교하지 않으며, ID로 이름이 바뀐 기업을 찾는 동작과 기록 순서를 유지한다.
- `plannerRevision`과 확장 화면 전용 `planner_snapshot` 요청을 추가했다. 메모·일정 저장은 확장 화면의 플래너만 갱신하고 채용 사이트 탭의 지원 기록을 다시 읽지 않는다. 지원 수정·삭제·초기화·복원은 기존 전체 갱신을 유지한다.
- 지원 기록은 100건씩 표시한다. 검색·필터·정렬을 바꾸면 첫 페이지로 이동하며, CSV에는 현재 페이지와 관계없이 검색 결과 전체를 넣는다.
- 검색·정렬·경로별 건수·메모 개수 계산을 재사용하고, 메모 개수의 연결×메모 이중 반복을 제거했다.
- 공고의 값이 바뀌지 않은 화면 갱신은 이력 안내의 재렌더를 생략한다. 클래스에 의존하는 선택자를 위해 DOM 파싱은 유지하며, 카드 복제·교체·기업 변경·설정 변경과 제거된 안내 복구는 계속 처리한다.

### 검증

- 타입 검사, 프로덕션 빌드, 단위 검사 31개 파일·377개 통과.
- 관련 브라우저 회귀 사례 총 30개 통과. 사람인 일반·추천 카드, 리멤버 목록, 잡코리아 검색과 기존 선택자, 원티드 공고 경고, 설정 변경, 자동 저장·다중 창 충돌·초기화·백업 복원, 메모 순서·크기 조절을 포함한다.
- 205개 지원 기록으로 페이지당 100행 제한, 마지막 페이지, 검색 초기화와 전체 결과 CSV 내보내기를 확인했다.
- 메모 저장 중 채용 탭에서 `snapshot` 요청이 발생하지 않고 확장 화면에서 `planner_snapshot`으로 갱신됨을 관찰했다.
- [390px 화면의 페이지 이동 버튼](images/records-pagination-mobile.png)을 확인했다.

검사는 임시 Chromium 프로필과 합성 문서로 수행했다. 실제 계정의 지원 동작은 수행하지 않았다. 새 의존성·접근 권한·데이터베이스 마이그레이션은 추가하지 않았다.

- 개인 구직·학습·평가를 위한 로컬 빌드와 비공개 수정을 허용한다.
- 소스·수정본·설치 파일 재배포, 스토어 등록, 상업적 이용과 타인 대상 서비스는 사전 서면 허가가 필요하다.
- 개인 사용 허가는 지원 이력·메모·계정 정보 등을 개발자나 제3자 수집처로 보내는 기능을 추가하거나 사용하는 권한을 포함하지 않는다.
